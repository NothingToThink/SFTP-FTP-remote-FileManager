# AGENTS.md — правила для ИИ-агентов и людей

Этот файл читают агенты (Claude Code, Codex и другие) перед работой в репозитории.
Правила обязательны и для людей. Если задача противоречит правилу — остановись и спроси в PR.

## Проект

SFTP/FTP-файловый менеджер, учебный проект команды **volcanoboys** (СП СПбГУ). .NET 10, C#.

| Проект | Что это |
| --- | --- |
| `Core` | Протоколы (`LocalConnection`, `FtpConnection`, `SftpConnection`), SSH-сессия, проброс портов, профили, known hosts |
| `Backend` | ASP.NET Core API на `127.0.0.1`. Клиент работает только через него |
| `Client` | Десктоп на Avalonia 12 + CommunityToolkit.Mvvm. С Backend общается по HTTP, на `Core` и `Backend` **не ссылается** |
| `Tests` | xUnit: юнит-тесты Core и интеграционные тесты Backend через `WebApplicationFactory<Program>` |
| `DevAudit` | Headless-аудит интерфейса клиента (сценарии, раскладка) |
| `ConsoleApp` | Заглушка, не развивать без задачи |

Известные баги — в `BACKEND-BUGS.md`. Не чини их попутно: только отдельной задачей и отдельным PR.

## Команды

```bash
dotnet build                                   # вся солюшен
dotnet test                                    # все тесты (то же запускает CI)
dotnet run --project Backend --urls http://127.0.0.1:5116
dotnet run --project Client
dotnet run --project Client -- --smoke http://127.0.0.1:5116   # контрактный smoke-тест, код 0 = ок
dotnet run --project DevAudit -- http://127.0.0.1:5116         # аудит UI
```

В тестах и экспериментах не трогай реальные данные пользователя — переопределяй папки:
`REMOTE_FILE_MANAGER_DATA_DIR` (Backend) и `FILEMANAGERCLIENT_DATA_DIR` (Client).
Swagger доступен в Development: `http://127.0.0.1:5116/swagger`.

## Ветки, коммиты, PR

- Ветка от свежего `dev`: `feature/<кратко>` или `fix/<кратко>`. PR — только в `dev`. `main` — релизы.
- Сообщения коммитов в стиле conventional commits, описание можно по-русски:
  `feat(tunnels): ...`, `fix(api): ...`, `test(api): ...`, `docs: ...`, `refactor(client): ...`.
- Одна задача — один PR, до ~400 строк изменений (без учёта сгенерированных файлов и миграций).
- Не переформатируй файлы, которые не меняешь по задаче. Отступы — 4 пробела.
- Не делай force-push в чужие ветки и никогда не переписывай историю `dev` и `main`.
- CI должен быть зелёным. Не отключай и не удаляй тесты, чтобы он позеленел.

### Без соавторов и подписей

- **Не добавляй строки соавторства** (`Co-Authored-By: ...`) ни в коммиты, ни в описание PR.
- Не добавляй подписи агента: `Generated with ...`, `Claude-Session: ...`, ссылки на сессии,
  упоминания модели или инструмента — ни в коммиты, ни в PR, ни в комментарии в коде.
- Автор коммита — git-пользователь, который запустил агента. Не меняй `user.name` и `user.email`.
- Для Claude Code это дополнительно закреплено в `.claude/settings.json` (`attribution`),
  а CI отклоняет PR, в коммитах или описании которого есть такие строки.

## Архитектурные правила

1. **Контракт API.** Клиент знает API только через `Client/Api/FileManagerApiClient.cs` и
   `Client/Models/ApiModels.cs`. Изменил или добавил эндпоинт — в том же PR обнови клиент,
   `Client/SmokeTest.cs` и интеграционный тест в `Tests/`.
2. **GET, HEAD и DELETE не читают тело.** Параметры — в route или query (`?path=`).
   Путь в query кодируется только через `Uri.EscapeDataString`: иначе `+` превратится в пробел.
3. **Удалённые пути — POSIX (`/`).** Не используй `Path.Combine` и другие методы `System.IO.Path`
   для путей на сервере: на Windows они вставят `\`. Старый код с этой ошибкой не трогай без задачи.
4. **Ошибки API** — JSON `{"error": "..."}`. Исключения переводит в коды `Backend/Middleware/ExceptionMiddleware.cs`.
   Новый тип ошибки — новая ветка там и тест на код ответа.
5. **Секреты** (пароли, passphrase, токены, ключи) не попадают в ответы API, логи и тексты ошибок.
6. **Файлы — потоками.** В новом коде не читай файл целиком в `MemoryStream`.
7. **Асинхронность.** Любой ввод-вывод — `async` с `CancellationToken`, без `.Result` и `.Wait()`
   в Backend и Core.
8. **JSON.** Ответы в camelCase. `HostProfile` сериализуется своим конвертером в PascalCase —
   не меняй это без задачи.
9. **Клиент.** Диалоги — только через `IDialogService`. Новые элементы UI получают
   `AutomationProperties.AutomationId`: по нему их находит DevAudit. Тексты интерфейса — по-русски.
10. **Зависимости.** Новый NuGet-пакет — только если без него никак; укажи причину в описании PR.

## Платформа плагинов

Работа идёт по спеке «Платформа плагинов — подготовка и SDK v0.1» (ссылку даст человек, ставящий задачу;
текст задачи для агента содержит всё нужное из спеки).

- Публичный API SDK (`FileManager.Plugins.Sdk`: интерфейсы, DTO, формат манифеста) меняет только
  человек — владелец SDK. Агент может предложить изменение в описании PR, но не вносит его сам.
- Id команд: встроенные — `fm.<область>.<действие>` (`fm.file.rename`), плагинов —
  `<издатель>.<плагин>.<действие>`. Издатель наших плагинов — `volcanoboys`.
- В SDK нет типов Core, SSH.NET и Avalonia. Всё, что уходит в Backend или UI, — async,
  с `CancellationToken`, на сериализуемых DTO.

## Перед открытием PR

- [ ] `dotnet build` без новых предупреждений, `dotnet test` зелёный.
- [ ] Трогал API или клиент — прогнан SmokeTest против локального Backend.
- [ ] Трогал UI — прогнан DevAudit.
- [ ] В коммитах и описании PR нет соавторов и подписей агента.
- [ ] Описание PR: что сделано, зачем, как проверено, номер задачи (например, «Фаза 0, задача 0.3»).
